# Міграції (spec.md §8, ADR 0007)

Три фази — три окремі кроки CD і окремі команди. Застосунок на старті міграцій **не** запускає.

| Фаза      | Файли               | Правило                                                                                                      | Команда                                 |
| :-------- | :------------------ | :----------------------------------------------------------------------------------------------------------- | :-------------------------------------- |
| `schema`  | `NNN_*.sql`         | DDL у транзакції, `lock_timeout` 5 с (+3 повтори). Лише expand: нова версія коду і попередня обидві працюють | `npm run db:migrate -- --phase=schema`  |
| `data`    | `data/NNN_*.sql`    | **один** ідемпотентний DML на пакет (`… WHERE id IN (SELECT … LIMIT 1000)`); повторюється, доки змінює рядки | `npm run db:migrate -- --phase=data`    |
| `indexes` | `indexes/NNN_*.sql` | **один** `CREATE INDEX CONCURRENTLY` на файл; поза транзакцією, без `statement_timeout`                      | `npm run db:migrate -- --phase=indexes` |

- Застосовані файли не редагуються; зміна — лише новим файлом.
- Contract-зміни (видалити колонку, яку читає попередня версія) — окремим релізом **після** того, як стара версія більше не працює.
- Seed (демо-дані) — не міграція: `npm run db:seed`.
- `001_init.sql` створено до розділення на фази; довідник `plans` у ньому — історичний виняток (вже застосовано, не редагується).
