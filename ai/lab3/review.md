# Lab 3 · Рев'ю: розбіжності spec ↔ вихід AI, і де «зелене» брехало

Правило (DoD §5): виправлення спершу у вході (`spec.md` / `AGENTS.md`), потім у коді чи тестах.

## Топ-3

### 1. Хибний mutation score: інструмент звітував 24 % без жодного запущеного тесту

- **Пункт spec:** §6.3 — mutation score ≥ 80 % з класифікацією вижилих.
- **Що зробив AI:** поставив найновіші версії, що відповідали політиці «≥ 2 тижні»: Vitest 5.0.5 і Stryker 10.0.0. Перший прогін дав 24,2 %, а `loader.service.ts` зі 100 % покриттям — 0 вбитих мутантів.
- **Як виявлено:** у `mutation.json` усі вижилі мали `testsCompleted: 0`. Зміна `coverageAnalysis` дала ідентичний результат. Раннер Stryker 10.0.0 (14.08) старший за Vitest 5 (03.09).
- **Виправлення:** Vitest зафіксовано на 4.1.12, і результат став реальним — 77,6 % (`99e289b`). Причину записано коментарем у `stryker.config.mjs` і в [mutation-report.md](../../docs/testing/mutation-report.md).
- **Урок для входу:** у `AGENTS.md` додано правило «0 % вбитих при високому покритті — спершу перевір інструмент».

### 2. «Зелені» тести при 100 % покритті не бачили зайвих запитів на гарячому шляху

- **Пункт spec:** §6.1 (100 % `loader`) виконано, але ADR 0003 / spec §1 вимагають мінімуму запитів на handshake (SLA).
- **Що згенерував AI:** 30 тестів `loader` перевіряли лише відповіді. Мутант `if (license.hwid === null)` → `if (true)` вижив: для прив'язаного ключа виконувався б зайвий `UPDATE` + `SELECT`, а результат лишався той самий.
- **Виправлення:** тест рахує виклики репозиторію — `{ find: 2, bind: 0 }` на два handshake (`9597d29`). Те саме сталося з логером (`pino({})` без `mixin` вижив, бо тестувалася функція, а не підключення) і з `config` (`min(1)` → `max(1)`). Повний розбір — mutation-report.
- **Виправлення входу:** правило в `AGENTS.md`: тест гарячого шляху фіксує **кількість звернень до сховища**, не лише відповідь.
