# Definition of Done (DoD) проєкту "License & Config Hub"

Цей документ визначає критерії завершеності для будь-якої задачі, фічі, модуля або лабораторної роботи в межах репозиторію.

---

## 1. Критерії якості коду та типізації

1. **TypeScript Strict Mode:**
   - Код компілюється командою `npm run typecheck` (`tsc --noEmit`) з **0 помилок**.
   - Повна відсутність типу `any` (жорстко контролюється правилом `@typescript-eslint/no-explicit-any`). Для невідомих типів використовується `unknown` з наступною Zod-валідацією.
   - Усі функції, методи та публічні API мають явний тип повернення (`@typescript-eslint/explicit-function-return-type`).
   - Увімкнені перевірки: `noImplicitAny`, `strictNullChecks`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`.

2. **Статичний аналіз та форматування:**
   - `npm run lint` (`eslint .`) завершується з **0 warnings** і **0 errors**.
   - `npm run format:check` (`prettier --check .`) підтверджує 100% відповідність кодстайлу.

---

## 2. Архітектурні обмеження (Modular Monolith)

1. **Розділення шарів (Separation of Concerns):**
   - **Transport (Routes/Controllers):** Тільки валідація схем (Fastify JSON Schema / Zod), маппінг HTTP-запитів і виклик доменного сервісу. Жодної бізнес-логіки.
   - **Domain / Service:** Чиста бізнес-логіка, валідація інваріантів, обробка доменних винятків. Не залежить від об'єктів `FastifyRequest` / `FastifyReply`.
   - **Data Access (Repository):** Ізольовані запити до БД (Drizzle ORM / SQL). Прямий доступ до бази з контролерів заборонено.

2. **Модульні межі:**
   - Модулі (`auth`, `licenses`, `configs`, `loader`) ізольовані у `src/modules/`.
   - Критичний шлюз `loader` відокремлений від загального модуля `licenses` для збереження SLA швидкодії.

---

## 3. Автоматизація конвеєра та Git-хуки

1. **Pre-commit хук (`.husky/pre-commit`):**
   - Автоматично запускає `lint-staged` (форматування Prettier + автофікс ESLint для staged `.ts` файлів).
   - Запускає `npm run typecheck`.
   - Спроба закомітити невідформатований код або код із помилками типізації **гарантовано блокується**.

2. **Pre-push хук (`.husky/pre-push`):**
   - Запускає `npm run build` (компіляція TypeScript у `dist/`).
   - Запускає `npm run smoke` (перевірка запуску екземпляра сервера).

3. **Conventional Commits:**
   - Усі повідомлення комітів мають чіткий префікс (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `test:`).
   - Заборонено використання прапорця `--no-verify`.

---

## 4. Відтворюваність та артефакти

1. **Smoke-тест:**
   - Сервер підтримує автономну самоперевірку працездатності: `npm run smoke`.
   - Smoke-тест ініціалізує плагіни, підтверджує готовність `app.ready()` та коректно завершує процес з кодом `0`.

2. **Контракт версіонування:**
   - Ендпоінт `GET /version` повертає статус `OK` та актуальний коміт із `GIT_COMMIT` або fallback-значення.

3. **Архітектурні рішення (ADR):**
   - Будь-яке принципове технічне рішення (вибір фреймворку, відхилення сторонніх бібліотек, межі контекстів) оформлюється у `standards/adr/` у форматі MADR.

4. **Захист (DEFENSE.md):**
   - Кожна лабораторна супроводжується лаконічним файлом `DEFENSE.md` (до 1 сторінки), що містить опис, топ-3 зрізані кути / розбіжності з посиланнями на коміти, ключовий ADR та команди перевірки.
