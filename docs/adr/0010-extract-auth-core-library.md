# 10. Виніс `auth` у бібліотеку `@lch/auth-core` з DI і admission control хешування паролів

- **Статус:** Прийнято (рішення студента 2026-11-09, варіанти — [`ai/lab5/02-findings.md`](../../ai/lab5/02-findings.md))
- **Дата:** 2026-11-09

## Контекст

Виміри на стенді (1 vCPU, [ADR 0009](0009-performance-measurement-tooling.md); [`docs/perf/load-baseline.md`](../perf/load-baseline.md), [`load-sweep.md`](../perf/load-sweep.md)):

| Факт                                                   | Число                                                                                                                       |
| :----------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------- |
| Вартість запиту                                        | handshake ≈ 0,5 мс CPU; **login ≈ 23 мс CPU** (scrypt, N=16384), ELU login лише 2 % — робота в потоках libuv                |
| Насичення                                              | handshake: 1 440 RPS при p99 2,7 мс; **login: обвал між 40 і 80 RPS** — p50 3,7 с, p99 7,1 с, 961 dropped                   |
| Вплив на сусідів (`storm`: 400 handshake + 60 login/с) | handshake p99 **1,6 → 86 мс** (SLA 50 мс), login p99 6,4 с                                                                  |
| БД                                                     | гарячі запити auth/loader — 0,03–0,05 мс за індексом ([`explain-baseline.md`](../perf/explain-baseline.md)): БД не боттлнек |

Найвразливіший модуль — `auth`. Найнижча точка насичення, обвал замість плавної деградації, і він ламає SLA найгарячішого шляху `loader` через спільний CPU. Вхід — публічний ендпоінт без rate limit (spec §7), тож шквал може влаштувати будь-хто.

Завдання 5: винести найвразливіший модуль в окрему бібліотеку. Залежності (БД, ресурси) — через DI, публічний контракт типізований, базовий модуль не знає реалізацій.

## Чинники рішення

1. Login-шквал не має права забрати CPU, потрібний іншим модулям (spec §9: storm → handshake p99 ≤ 50 мс).
2. Перевантаження — швидка відмова, а не черга на секунди.
3. Бібліотека не знає Postgres, Fastify, `node:crypto`, AsyncLocalStorage — і це перевіряє машина, а не рев'ю.
4. Без нових рантайм-залежностей.

## Рішення

1. **`packages/auth-core`** — npm workspace `@lch/auth-core` зі своїм `package.json`. Exports: `source` → `src/index.ts` (розробка, тести), `types`/`default` → `dist/` (продакшен-збірка). Публічний контракт — [`contract.ts`](../../packages/auth-core/src/contract.ts).
2. **DI одним об'єктом** `AuthDeps`: `store: AuthStore` (БД), `hasher: PasswordKdf`, `clock: Clock`, `tokens: SessionTokens`, `currentUser: CurrentUser`, `logger: AuthLogger`, `sessionTtlMs`. Пакет не має жодного `import` поза своїм `src/`.
3. **`createPasswordHasher(kdf, { maxConcurrent, maxQueued })`** — семафор + FIFO-черга. Слот передається від завершеного виклику наступному, а не звільняється й захоплюється знову, тож нових запитів «між» немає. Повна черга → `AuthError('AUTH_BUSY')`. За замовчуванням `AUTH_HASH_CONCURRENCY=1`, `AUTH_HASH_QUEUE=8`: очікування ≤ 8 × ~22 мс ≈ 180 мс → login p99 у SLA 500 мс. На багатоядерному prod — `ядра − 1`.
4. **Хост** ([`auth.adapters.ts`](../../src/modules/auth/auth.adapters.ts)): scrypt-KDF (`node:crypto`), SHA-256 токенів, `getContext()` як `CurrentUser`, pino як логер. `toAppError` перетворює `AuthError` на коди spec §3 в **одному** глобальному обробнику.
5. **Межу перевіряє лінт:** для `packages/*/src` ESLint забороняє `**/src/*`, `../../*`, `node:*`, `postgres`, `fastify`, `pino`, `zod`, `crypto`, `fs`.

## Наслідки

- ✅ Пакет тестується без БД і крипто: фейкові порти, 100 % покриття як поріг, мутаційне тестування.
- ✅ Інша реалізація (argon2, інше сховище, інший транспорт) — нова реалізація порту в хості, пакет не змінюється.
- ✅ Новий код `AUTH_BUSY` (503) у spec §3; фронт показує зрозуміле повідомлення.
- ⚠️ Справжнє зниження вартості логіну неможливе без послаблення KDF. Admission control не робить login дешевшим, а лише не дає йому зламати решту сервісу.
- ⚠️ Збірка застосунку тепер спершу збирає пакет (`npm run build`), а dev-запуски мають умову `--conditions=source`.
- ❌ Rate limit за IP/акаунтом (захист від перебору паролів) свідомо не входить у лабу — продуктовий трек ([`docs/product/web.md`](../product/web.md)).
