# 1. Фіксація архітектурних рішень через MADR

- **Статус:** Прийнято
- **Дата:** 2026-09-30 (доповнено до повного MADR 2026-11-05)

## Контекст

Проєкт ухвалює рішення, які треба захищати на 5-хвилинному рев'ю: фреймворк, межі модулів, БД, спосіб композиції. Без журналу рішень контекст і причини вибору губляться. Зокрема, при роботі з AI незрозуміло, хто й чому обрав варіант.

## Чинники рішення

1. Рев'юер має зрозуміти рішення за 1–2 хвилини.
2. Рішення живе поруч із кодом, у git, з історією змін.
3. Кожен відхилений варіант має явні плюси й мінуси (вимога DoD курсу).

## Розглянуті варіанти

| Варіант                                        | Плюси                                                                            | Мінуси                                                           |
| :--------------------------------------------- | :------------------------------------------------------------------------------- | :--------------------------------------------------------------- |
| **MADR у `docs/adr/`, обрано**                 | Стандартні поля (чинники, варіанти з плюсами/мінусами, наслідки); Markdown у git | Час на оформлення                                                |
| Nygard ADR (Context / Decision / Consequences) | Найкоротший формат                                                               | Немає місця для варіантів з плюсами/мінусами — вибір не пояснено |
| Вікі / Google Docs                             | Зручно редагувати                                                                | Відірвано від коду й комітів, немає історії в PR                 |

## Рішення

Кожне суттєве рішення — файл `docs/adr/NNNN-short-title.md` за MADR: Статус, Контекст, Чинники, Розглянуті варіанти (кожен з плюсами й мінусами), Рішення, Наслідки. Рішення не редагуються заднім числом: зміна оформлюється новим ADR зі статусом «Замінює NNNN».

## Наслідки

- **Позитивні:** DEFENSE посилається на ADR одним рядком; видно, що варіанти зважувалися.
- **Негативні:** додатковий час на документування. Ризик формальних ADR без справжніх альтернатив.
