# 8. Фронтенд: React + Vite SPA на тому самому origin, що й API

- **Статус:** Прийнято
- **Дата:** 2026-11-09

## Контекст

Продукту потрібен вебкабінет: вітрина тарифів, вхід і реєстрація, мої ліцензії, стан замовлення. Далі — конфіги й адмінка. Лаба 5 вимірює фронт Lighthouse. Стейдж — один free-сервіс Render ([ADR 0006](0006-ci-cd-github-actions-render-neon.md)). Пізніше буде власний VPS.

API автентифікує непрозорим Bearer-токеном. Перехід на httpOnly-cookie — відкрите продуктове рішення ([`docs/product/web.md`](../product/web.md)).

Стек і схему розгортання обрав студент 2026-11-09.

## Чинники рішення

1. Студент розвиватиме фронт сам: потрібні велика екосистема й ринок.
2. Один деплой, один артефакт: CD з ADR 0006 без нових сервісів.
3. Без CORS і зі шляхом до httpOnly-cookie без переробки.
4. Статична збірка: роздати може будь-хто (Fastify зараз, Caddy/nginx на VPS).

## Розглянуті варіанти

### Стек

| Варіант                          | Плюси                                                                  | Мінуси                                                                                     |
| :------------------------------- | :--------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| **React 19 + Vite + TS, обрано** | Найбільша екосистема й ринок праці; зрілі бібліотеки форм, запитів, UI | Бандл важчий (≈ 103 КБ gzip каркасу) — предмет оптимізації в Лабі 5                        |
| Vue 3 + Vite                     | Нижчий поріг входу, шаблони близькі до HTML                            | Менша екосистема                                                                           |
| Svelte 5                         | Найменший бандл, кращий Lighthouse «з коробки»                         | Менша екосистема й ринок                                                                   |
| Next.js / SSR                    | SEO, швидший перший рендер                                             | Окремий Node-сервер для рендеру: другий сервіс, складніший деплой; кабінет не потребує SEO |

### Розгортання

| Варіант                                                 | Плюси                                                                            | Мінуси                                                                       |
| :------------------------------------------------------ | :------------------------------------------------------------------------------- | :--------------------------------------------------------------------------- |
| **Той самий origin: Fastify роздає `web/dist`, обрано** | Один образ, один деплой; без CORS; cookie `SameSite=Strict` працюватиме без змін | Статику роздає Node, а не CDN; фронт і API деплояться лише разом             |
| Окремий Render Static Site (CDN)                        | Швидша роздача, незалежні деплої                                                 | Два сервіси; CORS-allowlist; cookie між доменами (`SameSite=None`) складніші |

## Рішення

1. `web/` — окремий npm-пакет зі своїм lockfile: React-залежності не потрапляють у prod-залежності сервера. Маршрутизація — `react-router`.
2. Dev: Vite на `:5173` проксує `/api`, `/version`, `/health` на Fastify `:3000` — та сама модель origin, що й у prod.
3. Prod: стадія `web` у [`Dockerfile`](../../Dockerfile) збирає SPA → `/app/public`, `WEB_DIST_DIR=/app/public`. [`src/web.ts`](../../src/web.ts) реєструє `@fastify/static`:
   - `/assets/*` (хеш в імені) → `max-age=1 рік, immutable`;
   - решта → `no-cache`;
   - навігація браузера на невідомий шлях (`GET`, `Accept: text/html`, не `/api/`) → `index.html`;
   - API й не-HTML запити лишають JSON 404 зі spec §3.
4. Без `WEB_DIST_DIR` сервіс — лише API (тести, локальна розробка). Каталог без `index.html` → падіння на старті, а не на першому відвідувачі.
5. Лінт `web/` — той самий strict TypeScript ESLint + `react-hooks`; CI: `check` (lint, `tsc`), `build` (`vite build`), `docker` (SPA-оболонка з контейнера).

## Наслідки

- ✅ Перехід на VPS: та сама збірка `web/dist` віддається Caddy/nginx, API — за reverse proxy на тому самому домені.
- ✅ Деплой атомарний: фронт і API, що його обслуговує, завжди однієї версії (`/version`).
- ⚠️ `@fastify/static@10.1.10` — **виняток** із правила «реліз ≥ 2 тижнів»: 10.1.7 тягнув `glob` з advisory GHSA-3g3m-2fjr-6pw4 (moderate), виправлення лише в 10.1.9+. Це патч безпеки в тій самій minor-лінії.
- ⚠️ Токен у `localStorage` доступний скриптам сторінки (XSS) — свідомий компроміс каркаса до рішення про cookie.
- ❌ Автоматичних тестів компонентів фронту ще немає: перевірено збіркою, лінтом, `tsc` і ручним проходом. Пріоритет продуктового треку — [`docs/product/web.md`](../product/web.md).
