# 4. PostgreSQL і доступ через SQL tagged templates (`postgres`), без ORM

- **Статус:** Прийнято
- **Дата:** 2026-11-05
- **Замінює:** намір «Drizzle ORM у Лабі 2» з [`docs/defense/lab1.md`](../defense/lab1.md) (зрізаний кут №1)

## Контекст

Лаба 2 переводить усі сценарії зі статичних даних на реальну БД. Потрібні транзакції (вебхук оплати), атомарний compare-and-set (прив'язка HWID), ідемпотентні вставки (`Idempotency-Key`, `event_id`) і прозорий контроль кількості запитів (N+1). У Лабі 5 буде профілювання: `EXPLAIN ANALYZE` гарячого шляху `loader`. Модель даних — 7 таблиць, без поліморфізму.

## Чинники рішення

1. Повний контроль над SQL: `ON CONFLICT`, `FOR UPDATE`, `FOR KEY SHARE`, умовний `UPDATE … RETURNING`.
2. Видно, скільки запитів іде на один HTTP-запит (N+1).
3. Безпека від SQL-ін'єкцій без ручного екранування.
4. Мінімум рантайм-залежностей і кодогенерації (supply chain, ADR 0002).
5. Типізація результатів у strict TypeScript без `any`.

## Рішення

**PostgreSQL 17** + драйвер **`postgres@3.4.9`** (зафіксована версія: 4.0.0 вийшла за тиждень до рішення).

- SQL живе **лише** в `src/modules/*/*.repository.postgres.ts`. Транзакції (`sql.begin`) — теж лише там.
- Модель рядків описана один раз у [`src/shared/db/rows.ts`](../../src/shared/db/rows.ts) (camelCase через `transform`). Її повертають і in-memory, і Postgres-репозиторії.
- Схема — forward-only SQL-міграції в `migrations/`; мінімальний мігратор [`migrate.ts`](../../src/shared/db/migrate.ts) з advisory lock.
- Пул ініціалізується на старті + `SELECT now()` (fail fast). Локальна БД — `docker compose`, порт `55432`.

## Наслідки

**Позитивні**

- Атомарність виражено самим SQL: вебхук — одна транзакція з `FOR UPDATE` і `ON CONFLICT`; handshake — один `UPDATE … WHERE hwid IS NULL`.
- Лічильник `dbQueries` у кожному лозі запиту виявив реальний N+1 (`afab07d`: 9 → 2 запити).
- Ідемпотентні операції безпечно ретраяться (`withRetry`) на `40001`/`40P01`/обриві з'єднання.

**Негативні / компроміси**

- Розбіжність типу `Row` і схеми не ловиться компілятором — лише smoke-прогоном на БД (`npm run smoke:db`). Лаба 3 закриває це інтеграційними тестами на Testcontainers.
- Свій мігратор не вміє down-міграцій: відкат — новою міграцією.
