## Трасування: критерії `spec.md` §4 → тести

| Критерій §4                               | Де перевірено                                                                                                                                                                              |
| :---------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Сценарії через HTTP на обох джерелах   | `test/support/api-contract.ts` — **той самий** набір із 21 сценарію: `unit/api.memory.test.ts` і `integration/api.postgres.test.ts`                                                        |
| 2. Межі шарів                             | сервіси тестуються без Fastify (`unit/services/*`); SQL — лише в `integration/*.repository.postgres.test.ts`                                                                               |
| 3. Контекст і логи без параметрів         | `unit/shared/logger-wiring.test.ts` (реальний логер); `e2e` — усі рядки одного checkout з двох запитів мають один `processId` у справжньому stdout                                         |
| 4. Один глобальний обробник               | контракт: усі помилки у форматі `{error:{code,message},requestId,processId}`; 413/415 без кодів `FST_ERR_*`                                                                                |
| 5. Ідемпотентність                        | `integration/licenses…`: 10 паралельних `createOrder` з одним ключем → 1 рядок; одна подія ×10 → 1 PAID + 9 DUPLICATE                                                                      |
| 6. Гонка handshake                        | `integration/loader…`: 20 паралельних `bindHwid` → 1 переможець; контракт: 5 пристроїв → 1 `BOUND`                                                                                         |
| 7. Збої БД                                | `integration/db-resilience.test.ts`: fail fast, 503 + `Retry-After` після зупинки БД, відновлення після `pg_terminate_backend`, `57014` → 503 без ретраю; `e2e`: процес виходить з кодом 1 |
| 8. Без N+1                                | `integration/licenses…`: сторінка з 25 рядків = **1** SQL-запит                                                                                                                            |
| 9. Ізольоване середовище                  | Testcontainers: випадковий порт, нова БД на прогін; міграції застосовує той самий `runMigrations()`                                                                                        |
| 10. Паритет інваріантів memory ↔ Postgres | контракт: видача ліцензії неіснуючому користувачу → 404 на обох джерелах                                                                                                                   |
